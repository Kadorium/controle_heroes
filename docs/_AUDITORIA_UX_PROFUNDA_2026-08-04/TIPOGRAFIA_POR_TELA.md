# Tipografia por tela

Data: 2026-08-04. Leitura direta do JSX de cada tela em `v2/frontend/src/features/`. Todas as telas herdam `--font-ui` ("Segoe UI"/system-ui) do `:root` global — não há override de família de fonte em nenhuma tela individual.

## Convenção comum a quase todas as telas

- **Heading**: 100% das telas de listagem/detalhe usam o componente `PageHeader`, que renderiza `<h1>{title}</h1>` sem className própria — herda o CSS global `.page-header h1 { font-size: var(--font-size-title) /* 22px */; font-weight: 650; }` (`index.css:604-609`). O heading **vem do layout do componente `PageHeader`**, não da página — a página só passa a string `title`. Exceção: `LoginPage` não usa `PageHeader`; seu `<h1>` vem de `.login-form h1` (28px, hardcoded em rem, fora do token `--font-size-title`). `CustomsListPage`/`CustomsCreatePage`/`CustomsDetailPage`/`MovementsPage`/`SkuPositionPage` também usam `PageHeader`, então herdam os 22px — mesmo pertencendo ao módulo com CSS mais divergente (ver `LAYOUT_POR_TELA.md`).
- **Labels de formulário**: 100% dos formulários que usam o componente `FormField` têm label **acima do input** (`.form-field { display:grid; }`, label em `.form-field-label` = `var(--font-size-meta)` 12px, `index.css:1363-1365`). Não há nenhum padrão de label lateral ou flutuante no projeto. Placeholder-only (sem `<label>`) não ocorre em nenhum campo de formulário de negócio — só em campos de busca secundários dentro de tabelas legadas (ex.: `<TextInput placeholder="SKU" .../>` em `OrderCreatePage` linha 279, sem `FormField`/label associado, ver `INVENTARIO_INPUTS.md`).
- **Obrigatoriedade**: marcada por asterisco (`<span className="form-field-required">*</span>`, `index.css:1368-1370`) via prop `required` do `FormField`. Usado de forma inconsistente: `OrderCreatePage` marca "Código" e "Data do pedido" como `required`, mas não marca "Fornecedor" como obrigatório mesmo sendo de fato exigido pela lógica (`ensureSupplier()` lança erro se vazio) — ver `INVENTARIO_INPUTS.md`.
- **Células de tabela numéricas/monetárias**: quando a tabela usa o componente `OperationalTable` + `MoneyDisplay`/`formatQuantity`, a célula recebe `className="num"` e a string vem envolvida em `<span className="money" data-testid="money">` (dentro de `MoneyDisplay`) — CSS aplica `font-variant-numeric: tabular-nums; text-align:right` (`index.css:863-867`, `1085-1089`). Isso é consistente em Orders, Billing, Treasury. **Exceção**: `MovementsPage` e `SkuPositionPage` renderizam números (`Δ Qtd`, quantidades de bucket) em `<td>` puro sem `className="num"` nem `formatQuantity` (`MovementsPage` chama `formatQuantity(m.quantity_delta)` mas a `<td>` não tem `className="num"` — perde alinhamento à direita e tabular-nums).
- **Colunas de status**: quando presentes, usam `<StatusBadge>` (chip colorido) — Orders, Billing, Treasury, Customs (lista). Exceção: `CustomsDetailPage`, os 4 painéis de Aduana (Doganale/Numerário/Nationalization/Receipt) e `ShipmentDetailPage`/referências mostram status como **texto puro dentro de `<li>`** (ex.: `{nationalizationStatusLabel(n.status)}`), nunca como badge — perda de escaneabilidade visual justamente nas telas mais densas em estado (múltiplos status por processo aduaneiro).
- **Headers de tabela (`<th>`)**: quando via `OperationalTable`, herdam `font-size: var(--font-size-meta)` (12px) + `font-weight:600` + `color:var(--color-muted)` (`index.css:950-954`). Quando a tabela é HTML puro sem o componente (`LogisticsProvidersPage`, `PaymentFxPanel`/`.mini-table`, `CustomsDetailPage` auditoria), o `<th>` herda apenas o CSS genérico `.data-table th`/`.mini-table th` — visualmente parecido mas **não é a mesma regra CSS**, é uma duplicata paralela (`index.css:299-303` vs `1482-1486`).

## Problemas de hierarquia visual encontrados no código

1. **`.login-form h1` (28px) vs `.page-header h1` (22px)** — único heading fora da escala; usuário percebe o login como "maior" que o resto do app sem motivo declarado no código (não há comentário justificando).
2. **Duplicação de CSS de tabela**: `.data-table th` (12.8px, `index.css:299-303`) e `.mini-table th` (`var(--font-size-label)` 11px, `index.css:1482-1486`) e `.operational-table th` (`var(--font-size-meta)` 12px, `index.css:950-954`) são três regras quase idênticas para o mesmo papel visual ("cabeçalho de tabela"), aplicadas conforme qual componente/classe a tela escolheu usar — não há uma fonte única de verdade.
3. **Módulo Aduana sem `.num`/`StatusBadge`**: os 4 painéis usam texto corrido para dados que em qualquer outra tela do app seriam tabela com alinhamento numérico e badge de status — a diferença de densidade de informação e escaneabilidade entre "abrir uma fatura" e "abrir um processo aduaneiro" é grande e visível já no código, não é impressão subjetiva.
